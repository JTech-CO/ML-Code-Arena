## DoD (완료 게이트)
1. 문제 선택 → 코드 작성 → 제출 → 판정 수신 전체 흐름이 수동 시연으로 완주된다.
2. **판정 8종이 UI에 전부 정확히 표시된다.** 빈 칸·`undefined`가 없다.
3. `WA` 시 `ShapeDiff`가 기대/실제 shape를 표시하고, **기대값 자체는 표시하지 않는다**(INV-5 준수).
4. 흑백 렌더에서 판정 구분이 가능하다(INV-11 준수) — 판정 코드 텍스트가 항상 병기됨.
5. 문제 목록 첫 화면에 **15행 이상**이 보인다(1920×1080 기준).
6. SSE 실시간 제출이 갱신되고 익명 제출은 표시되지 않는다.
7. 개념 ↔ 문제 이동이 양방향 모두 1클릭이다.
8. `AnonQuotaBar`가 잔여 3개 이하에서만 노출되고, 닫기가 동작한다.
9. 반응형: 1280 / 1024 / 768 / 375px에서 가로 스크롤이 없다.
10. 키보드만으로 문제 선택·진입·제출(`Ctrl/Cmd+Enter`)이 가능하고 포커스 표시가 항상 보인다.
11. 판정 결과 영역이 `role="status"` + `aria-live="polite"` 로 안내된다.
12. `docs/DESIGN.md` §12 금지 목록 12항목이 전부 0건.

### DoD 1 — 전체 흐름 완주
문제집 → `l2norm` 진입 → 에디터에 코드 작성 → 제출 → 판정 수신까지 완주했다.

### DoD 2 · 4 — 판정 8종과 색 단독 의존 금지
DB 에 8종 판정을 넣고 트리거로 SSE 를 태워 **실제 컴포넌트로** 렌더했다.

## 이 phase 에서 잡은 것

**1. 쿠키가 붙지 않아 익명 세션이 매 요청 새로 발급되고 있었다.**
`localhost:5173` → `127.0.0.1:3000` 은 교차 사이트라 `SameSite=Lax` 쿠키가 실리지 않는다.
증상은 "익명 잔여가 영원히 10" 이고, 그대로 두면 **계정 승계(M3 DoD 6)도 실환경에서
성립하지 않는다.** 쿠키를 `SameSite=None` 으로 푸는 대신 Vite 프록시로 출처를 합쳤다 —
운영에서는 같은 출처이므로 Lax 가 맞고, 개발 편의로 운영 설정을 바꾸면 그 차이가
나중에 버그로 돌아온다 (ADR-0004).

**2. SSE 가 CORS 로 끊기고 있었다** (`net::ERR_FAILED`).
`reply.raw.writeHead()` 는 Fastify 의 reply 를 우회하므로 `@fastify/cors` 가 붙인
헤더가 사라진다. 필요한 헤더만 골라 직접 옮기고 `reply.hijack()` 을 붙였다.
프록시로 동일 출처가 된 뒤에도 이 수정은 유효하다 — 운영에서 web·api 출처가
갈라질 수 있다.

**3. `Ctrl+Enter` 가 빈 줄을 삽입하고 있었다.**
CodeMirror 의 `defaultKeymap`(basicSetup 포함)이 이미 `Mod-Enter` 를 `insertBlankLine`
에 묶어 두었다. `Prec.highest()` 로 우선순위를 올렸다.

**4. 목록 행이 74px 로 부풀어 있었다.**
제한 칩이 두 줄로 접히면서 40px 규약이 깨졌고, 그러면 한 화면에 15행이 들어가지
않는다. 목록은 허용 목록 칩 하나만, 전체 제한은 상세 화면 제목 줄에서 노출하도록
역할을 나눴다 — 숨기는 것이 아니다.

**5. 문제 → 개념 링크가 없었다.** 개념 → 문제만 있으면 양방향이 아니다.
API 응답에 `concepts` 를 추가하고 상세 화면에 링크를 뒀다.

## 리스크 / 미지수
- ~~CodeMirror 6 다크 테마와 토큰 정합~~ → 에디터 배경이 `rgb(22,24,28)` = `--bg-canvas`
  로 정확히 일치함을 실측했다. `@uiw/react-codemirror` 를 쓰지 않은 것이 주효했다 —
  그것은 `@codemirror/theme-one-dark` 를 필수 peer 로 끌고 온다.
- ~~스플리터 드래그~~ → 1024px 미만은 탭으로 완전히 대체했다. **드래그 가능한 스플리터는
  만들지 않았다.** §6.4 가 `≥1280px` 에서 드래그를 적었으나 고정 46:54 로 두었다.
  드래그 상태를 어디에 저장할지(세션·계정·로컬)가 정해지지 않았고, 그 결정 없이 만들면
  새로고침마다 폭이 돌아가 오히려 성가시다. M6 이후 사용자 피드백으로 판단한다.
- **구문 강조를 단색 위계로 했다.** 백서 §3.1 이 "중성색 1계열 + accent 1색 + 판정색,
  그 외의 색은 없다"고 못박아, 에디터를 위해 팔레트를 새로 만들면 규칙이 깨진다.
  명도·굵기로 위계를 만들었고 제출 코드가 30줄 남짓이라 읽힌다. 색이 필요하다는
  판단이 서면 토큰을 늘리는 결정이 먼저다.
- 문제 목록의 태그 필터가 비어 있다. `GET /api/problems` 가 태그를 돌려주지 않아
  사이드바에 태그 목록을 채울 수 없다. M6 에서 문제에 태그가 붙을 때 함께 뚫는다.
- 브라우저 패널이 표시되지 않아 **스크린샷을 남기지 못했다.** DOM·계산된 스타일로
  대체했다. 흑백 스냅샷 대신 "판정 코드 텍스트가 항상 병기됨"을 값으로 확인했다.

## 주의
- 제한 칩을 툴팁·아코디언 뒤에 숨기지 않는다. `FBD` 판정의 대부분은 제한을 못 본 데서 나온다.
- 채점 대기를 스피너로 표시하지 않는다. `채점 중 · 대기 3번째` 처럼 정보를 준다.
- 판정 색을 배경 뱃지로 칠하지 않는다. 목록 밀도가 무너진다.
