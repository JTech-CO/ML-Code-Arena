## 할 일
Docker Compose 구성(api·worker·postgres·redis) -> 리버스 프록시(SSE 버퍼링 해제) -> CI(빌드·린트·타입체크·테스트·대비 검사·디자인 린트) -> 로깅 -> 모니터링 지표 -> DB 백업 크론 -> 부하 시험.

## 참조

## DoD (완료 게이트)
1. 클린 호스트에서 `docs/ENVIRONMENT.md` 절차만으로 전체 스택이 기동된다.
2. CI가 그린이며, 게이트에 대비 검사(INV-12)와 디자인 린트가 포함된다.
3. 부하 시험: 동시 제출 50건에서 유실 0건, 채점 완료 P95 < 5초, `IE` 비율 0.5% 미만.
4. SSE가 프록시 뒤에서 5분 이상 끊기지 않는다.
5. 모니터링 지표 4종이 수집된다 — 큐 대기 길이, 판정 분포, 워커 실패율, 익명→가입 전환율.
6. `IE` 비율이 0.5%를 넘으면 알림이 발생한다.
7. DB 일일 백업이 실행되고, 백업본으로 클린 DB 복구가 성공한다.
8. 시크릿이 `.env`로만 주입되고 이미지·저장소에 포함되지 않는다(INV-1 준수).
9. 워커 컨테이너가 최소 권한으로 실행되며, 워커 자체는 사용자 코드를 실행하지 않는다.

## 롤백 계획
이미지 태그를 커밋 SHA로 고정하고 이전 태그로 즉시 되돌린다. DB 마이그레이션은 down을 함께 배포한다.

## 리스크 / 미지수
- Docker 소켓 마운트는 호스트 루트 권한과 동등하다. 워커를 전용 호스트에 격리하거나 rootless로 전환하는 결정이 필요하다(ADR-0007 후보).
- 단일 호스트이므로 워커 장애가 곧 서비스 중단이다. Phase 1 규모에서는 수용하되 복구 절차를 런북에 둔다.

## 주의
"배포됐다"가 완료가 아니다. **문제가 생겼을 때 알아차릴 수 있는가**가 완료 기준이다. 게이트 5·6번이 그 판정이다.
