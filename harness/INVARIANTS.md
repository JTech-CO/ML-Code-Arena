# INVARIANTS.md — 불변식 레지스트리

> 불변식은 "절대 일어나면 안 되는 일"이다. 일반 DoD와 달리, **1건이라도 위반되면 통과 금지**. DoD와 레드라인은 여기 ID(INV-n)를 참조한다. 새 불변식은 ID를 부여해 추가하고, 폐기 시 줄을 지우지 말고 상태를 `폐기`로 표시한다.

## 등록 규칙
- 검증 가능한 형태로 쓴다(명령·테스트·자동 점검으로 확인되게).
- "범위"에 어느 phase/모듈에 적용되는지 명시.
- DoD에서 `(INV-3 준수)`처럼 인용한다.

## 레지스트리

| ID | 불변식 | 범위 | 검증 방법 | 상태 |
|---|---|---|---|---|
| INV-1 | 시크릿(`.env`·키·토큰)을 커밋하지 않는다 | 전역 | pre-commit 시크릿 스캔, CI | 활성 |
| INV-2 | 대용량 산출물(테스트 데이터·빌드물·이미지)을 커밋하지 않는다 | 전역 | `.gitignore`, CI 크기 점검 | 활성 |
| INV-3 | 모듈 경계를 위반하는 상호 import가 없다 | 전역 | eslint 경계 룰(`docs/FILE_TREE.md` §3) | 활성 |
| INV-4 | 채점 컨테이너는 네트워크에 접근할 수 없다 | 워커·러너 | 컨테이너 내부에서 외부 호출 시도 → 실패 확인 테스트 | 활성 |
| INV-5 | 기대값(expect)이 사용자에게 도달하는 경로가 없다 | 러너·API | API 응답·에러 문자열·클라이언트 번들 grep, 응답 스키마 테스트 | 활성 |
| INV-6 | AST 정적 검사는 사용자 코드 import보다 **먼저** 실행된다 | 러너 | 모듈 최상위에 부작용 코드를 둔 금지 샘플 제출 → 부작용 미발생 + `FBD` | 활성 |
| INV-7 | 테스트케이스 직렬화에 pickle을 사용하지 않는다 | 문제 정의·러너 | ① **활성화** 사용 0건 grep(`allow_pickle=True`·`import pickle`·`.pkl`) ② 객체 dtype `.npz` 거부 테스트 ③ 로더 태그·dtype 화이트리스트 | 활성 |
| INV-8 | 채점 컨테이너는 제출 1건당 새로 생성되며 재사용되지 않는다 | 워커 | 연속 제출 시 컨테이너 ID 상이 확인, 전역 상태 오염 테스트 | 활성 |
| INV-9 | 익명 제한 카운트는 서버에서만 증가하며 클라이언트 값을 신뢰하지 않는다 | API | 조작된 요청으로 카운트 우회 시도 → 차단 확인 | 활성 |
| INV-10 | 문제의 기대값은 `reference.py`로 생성하며 손으로 작성하지 않는다 | 문제 정의 | `problem-sync --verify`로 전 문제 기대값 재생성 후 해시 일치 | 활성 |
| INV-11 | 판정은 색 단독으로 표현되지 않는다 — 판정 코드 텍스트를 항상 병기 | UI | 흑백 렌더 스냅샷에서 판정 구분 가능 확인 | 활성 |
| INV-12 | 다크 모드가 순수 `#000` 배경을 쓰지 않으며, 모든 텍스트 대비가 4.5:1 이상이다 | UI | 토큰 대비 자동 검사 스크립트(CI) | 활성 |

## 주석

**INV-4·INV-8이 함께 있는 이유**: 네트워크만 막고 컨테이너를 재사용하면 이전 제출이 `/tmp`에 남긴 파일을 다음 제출이 읽는다. 두 불변식은 하나의 격리 전제를 두 각도에서 지킨다.

**INV-6의 실질**: 순서가 역전되면 `import solution` 시점에 모듈 최상위 코드가 실행되므로, AST 검사가 통과 여부를 판정하기 전에 이미 임의 코드가 돈다. 검사 자체가 무의미해진다.

**INV-7의 검증이 "존재"가 아니라 "활성화"인 이유** (2026-08-06 개정): 로더가 위험한 역직렬화를 **끄는** 코드(`allow_pickle=False`)에도 같은 단어가 들어간다. 단순 문자열 검색은 집행 지점을 위반으로 오인하고, 그걸 피하려고 명시적 방어를 지우면 보호가 기본값에 의존하게 된다. 검증 목표는 "그 단어가 없다"가 아니라 "오염된 파일이 실제로 거부된다"이므로, 적대적 `.npz` 거부 테스트를 함께 요구한다.

**INV-10의 실질**: 기대값을 손으로 쓰면 부동소수점 자릿수·shape·dtype이 미묘하게 어긋나 정답 제출이 `WA`로 판정된다. 이 오류는 사용자가 신고하기 전까지 발견되지 않는다.

M1 에서 이것이 실측으로 확인됐다. 같은 문제·같은 시드인데 호스트 numpy(2.3.4)와 컨테이너 numpy(2.4.6)의 케이스 해시가 달랐다. 기대값은 채점이 실제로 도는 환경에서 생성해야 한다.
