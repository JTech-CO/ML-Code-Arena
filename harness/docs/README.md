# docs/ — 백서 세트 (무엇을 만드는가)

> 하네스가 "어떻게"라면, `docs/`는 "무엇을". 각 phase는 작업 전 관련 백서 절을 읽는다.

## 문서 목록

| 문서 | 내용 | 상태 |
|---|---|---|
| `TECHNICAL.md` | 기술 백서 Phase 1 — 범위·아키텍처·채점 엔진·격리·데이터 모델·API·인증·문제 포맷·운영 | v0.1.0 |
| `DESIGN.md` | 디자인 백서 Phase 1 — 시그니처·토큰·타이포·레이아웃·컴포넌트·테마·모션·접근성·카피·금지 목록 | v0.1.0 |
| `FILE_TREE.md` | 디렉터리 구조와 모듈 경계 규칙 (INV-3 근거) | v0.3.0 |
| `ENVIRONMENT.md` | 로컬·CI 셋업, 환경변수, 실행·검증 명령, 자원 요건 | v0.1.0 |

## 갱신 규칙

백서와 구현이 어긋나면 **백서를 고치고 버전을 올린다.** 코드가 백서를 조용히 앞서가면 다음 세션의 Claude Code가 잘못된 전제로 작업한다. 백서 변경이 결정을 수반하면 `decisions/`에 ADR을 남긴다.
