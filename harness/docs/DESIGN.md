## 1. 디자인 브리프

### 1.1 대상

ML 알고리즘을 라이브러리 없이 직접 구현해보려는 학습자. 한국어권이 1차, 영어권이 2차. 대부분 코드 에디터와 문서를 오래 들여다보는 데 익숙한 사용자다.

### 1.2 화면의 단일 목적

**"어떤 문제를 풀지 고르고, 코드를 쓰고, 왜 틀렸는지 안다."**

이 세 동작 외의 모든 화면 요소는 부차적이다. 마케팅 히어로, 통계 카운터, 제품 소개 섹션은 이 사이트에 없다.

### 1.3 레퍼런스 태도

코드업(codeup.kr)의 **정보 구조와 밀도**를 벤치마킹하고, **시각 언어는 벤치마킹하지 않는다.**

| 가져올 것 | 버릴 것 |
|---|---|
| 문제집 단위의 조직 (플랫 리스트가 아닌 묶음) | Bootstrap 3 패널·라운드 박스 |
| 조밀한 테이블 행, 한 화면에 많은 문제 노출 | 12px 이하 본문, 좁은 행간 |
| 상시 노출 상단 내비 (햄버거 없음) | 기본 브라우저 링크 파랑/보라 |
| 판정을 짧은 텍스트 코드로 표기 | 문제 페이지와 제출 페이지의 분리 |
| 내부 페이지의 장식 없는 구성 | 난이도 구분·태그 부재 |

코드업의 가장 큰 구조적 약점은 난이도와 태그가 없어 탐색이 순번에만 의존한다는 점이다. 우리는 단계·난이도·태그·제한 4축을 도입해 이 지점을 보완한다.

### 1.4 반드시 아닌 것

레퍼런스를 따르되 다음으로 수렴하지 않는다. 이 셋은 현재 AI 생성 디자인의 기본값이며, 선택이 아니라 관성이다.

- 크림색 배경 + 고대비 세리프 + 테라코타 accent
- 순수 검정 배경 + 단일 형광 accent
- 브로드시트 스타일 헤어라인 + radius 0 + 신문 조판

## 2. 디자인 시그니처

이 사이트를 기억하게 만드는 단 하나의 규칙을 정한다. 나머지는 전부 조용하게 둔다.

### 2.1 측정값과 서술의 이원 규칙

> **측정된 것은 mono, 서술된 것은 sans.** 예외 없음.

| mono (JetBrains Mono) | sans (Pretendard) |
|---|---|
| 문제 번호, 정답률, 실행 시간, 메모리 | 문제 제목, 설명, 개념 문서 |
| 판정 코드 (`AC` `WA` `FBD`) | 내비, 버튼 라벨, 안내 문구 |
| shape 표기 `(3, 3)`, 허용 오차 `1e-5` | 사용자 핸들, 태그 이름 |
| 엔트리포인트 시그니처 `solve(x0, lr, n)` | 빈 상태·오류 메시지 |
| 제한 칩 `numpy만`, `sklearn 금지` | 단계 이름 |

**정당화**: 온라인 저지에서 사용자가 실제로 수행하는 행위는 "세로로 늘어선 수치를 눈으로 비교하는 것"이다. `font-variant-numeric: tabular-nums`로 자릿수가 정렬되면 정답률 열과 실행 시간 열을 스캔하는 속도가 실측 가능하게 빨라진다. 이것은 취향이 아니라 기능이다.

이 규칙이 일관되게 적용되면 테이블의 수치 열이 서술 열과 **다른 재질처럼** 보인다. 그것이 이 사이트의 인상이 된다.

### 2.2 제한 칩 (Restriction Chip)

문제 목록 테이블에 **제한** 전용 열을 둔다. 일반 저지에는 존재하지 않는 열이며, 이 플랫폼의 정체성이다.

```
numpy만        허용 import가 numpy로 한정
sklearn 금지   특정 라이브러리만 차단
직접 구현      allowed_imports가 표준 라이브러리뿐
```

문제를 열기 전에 "무엇을 스스로 만들어야 하는가"가 보인다. 이것이 ML Code Arena를 캐글·리트코드와 구분하는 지점이며, 목록 화면에서부터 드러나야 한다.

### 2.3 shape 대조 블록

`WA` 판정 시 기대 shape와 실제 shape를 mono로 세로 정렬해 보여주는 전용 블록. ML 입문자의 최다 오류가 축(axis) 실수이므로, 이 블록 하나가 오답 피드백의 대부분을 담당한다.

```
기대 shape   (3, 3)
실제 shape   (3,)
```

기대값 자체는 노출하지 않는다. shape만 노출한다.

## 3. 색상 시스템

### 3.1 원칙

중성색 1 계열 + accent 1색 + 판정 상태색. 그 외의 색은 없다.

판정색은 "이 색이 없으면 정보 전달이 깨지는가"라는 질문을 통과한다. 제출 목록에서 성공과 실패를 스캔하는 것은 색 없이 불가능하다. 다만 **색만으로 구분하지 않고 판정 코드 텍스트를 항상 병기**한다.

### 3.2 라이트 모드 (기본값)

```css
--bg-canvas:        #FFFFFF;   /* 본문 표면 */
--bg-subtle:        #F6F7F8;   /* 페이지 바탕, 테이블 헤더 */
--bg-inset:         #EEF0F2;   /* 코드 블록, 입력 필드 */
--bg-hover:         #F0F1F3;

--border:           #D8DCE0;   /* 기본 구분선 */
--border-strong:    #BFC5CB;   /* 호버, 활성 */

--text-primary:     #16191D;
--text-secondary:   #565E68;
--text-muted:       #6B737D;

--accent:           #1F5FA8;   /* 링크, CTA, 포커스, 활성 탭 */
--accent-hover:     #184C87;
--accent-bg:        #EAF1F9;
```

### 3.3 다크 모드

```css
--bg-canvas:        #16181C;   /* 순수 검정 사용 안 함 */
--bg-subtle:        #1D2025;
--bg-inset:         #24282E;
--bg-hover:         #262A30;

--border:           #2E333A;
--border-strong:    #3D444D;

--text-primary:     #E4E7EB;
--text-secondary:   #A8B0B9;
--text-muted:       #7C858F;

--accent:           #5B9BE0;
--accent-hover:     #79AFE8;
--accent-bg:        #1A2735;
```

### 3.4 판정 색상

| 판정 | 의미 | 라이트 | 다크 |
|---|---|---|---|
| `AC` | 정답 | `#1A7A45` | `#4EBE7F` |
| `WA` | 오답 | `#B32A28` | `#E8706B` |
| `TLE` `MLE` | 초과 | `#9A6206` | `#D9A23D` |
| `FBD` | 금지 사용 | `#6B3FA0` | `#A98CDB` |
| `RE` `CE` | 오류 | `#6B737D` | `#8B939D` |
| `PENDING` `JUDGING` | 대기·채점 중 | `#6B737D` | `#7C858F` |

**`FBD`에 고유 색(보라)을 부여하는 근거**: 다른 판정과 성격이 다르다. 코드가 실행조차 되지 않았고, 실력 문제가 아니라 규칙 위반이다. 오답과 같은 빨강으로 표시하면 사용자가 알고리즘을 의심하게 되는데, 실제로 고쳐야 할 것은 import 문이다. 이 플랫폼 고유 판정이므로 고유 색을 갖는다.

판정색은 **텍스트 색으로만** 사용한다. 배경 뱃지로 칠하지 않는다. 목록에서 20개 행이 전부 색 블록이 되면 밀도가 무너진다. 예외는 결과 패널 1곳으로, 판정 확정 시 패널 좌측에 3px 색 레일을 둔다.

### 3.5 대비 검증

| 조합 | 대비비 | 기준 |
|---|---|---|
| `--text-primary` on `--bg-canvas` (light) | 16.9:1 | AAA |
| `--text-muted` on `--bg-canvas` (light) | 4.8:1 | AA |
| `--accent` on `--bg-canvas` (light) | 6.5:1 | AA |
| `AC` on `--bg-canvas` (light) | 5.4:1 | AA |
| `WA` on `--bg-canvas` (light) | 6.4:1 | AA |
| `TLE` on `--bg-canvas` (light) | 5.2:1 | AA |
| `FBD` on `--bg-canvas` (light) | 7.4:1 | AAA |

다크 모드 토큰도 동일 기준으로 검증한다. 구현 시 자동 검사 스크립트를 CI에 포함한다.

## 4. 타이포그래피

### 4.1 서체

| 역할 | 서체 | 근거 |
|---|---|---|
| 서술 | Pretendard | 한글·라틴 혼용 시 글자폭 균형, 기존 컨벤션 |
| 측정값·코드 | JetBrains Mono | `0`/`O`, `1`/`l` 구분 명확, 코드 에디터와 동일 서체 |

**서체는 2종을 넘지 않는다.** 이모지 폰트는 사용하지 않는다.

### 4.2 스케일

```
32px / 700 / 1.25   페이지 제목 (문제 제목, 개념 문서 제목)
24px / 700 / 1.3    섹션 제목
20px / 500 / 1.4    소제목
16px / 400 / 1.7    본문 (문제 설명, 개념 문서)
15px / 400 / 1.6    보조 본문
14px / 400 / 1.5    테이블 셀, 폼 라벨
13px / 400 / 1.5    메타 정보 (타임스탬프, 캡션)
```

weight는 **400 / 500 / 700 세 단계만** 사용한다. 100·300 등 얇은 weight는 사용하지 않는다.

### 4.3 mono 규칙

```css
.mono {
  font-family: "JetBrains Mono", ui-monospace, monospace;
  font-variant-numeric: tabular-nums;
  font-size: 0.9375em;   /* sans 대비 시각 크기 보정 */
  letter-spacing: 0;
}
```

JetBrains Mono는 동일 px에서 Pretendard보다 크게 보이므로 `0.9375em`으로 보정한다. `letter-spacing`은 조정하지 않는다.

### 4.4 금지

- 음수 트래킹 `-0.03em` 초과
- 헤드라인 `line-height` 1.2 미만
- 본문 15px 미만
- 그라데이션 텍스트 (`background-clip: text`)
- ALL CAPS 제목 (제한 칩·판정 코드의 대문자 약어는 예외)

## 5. 간격과 형태

### 5.1 간격 스케일

4px 기반. `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`. 이 외의 값은 사용하지 않는다.

| 용도 | 값 |
|---|---|
| 테이블 셀 패딩 | `8px 12px` |
| 카드 내부 패딩 | `16px` |
| 섹션 간 여백 | `32px` |
| 페이지 좌우 여백 (데스크톱) | `24px` |
| 폼 요소 간격 | `12px` |

### 5.2 모서리

| 요소 | radius |
|---|---|
| 버튼, 입력, 카드, 코드 블록 | `6px` |
| 제한 칩, 태그 | `4px` |
| 아바타 | `50%` |

`12px` 이상의 큰 radius는 사용하지 않는다.

### 5.3 경계와 그림자

구분의 기본 수단은 **1px 경계선과 배경색 차이**다. 그림자가 아니다.

| 그림자 사용처 | 값 |
|---|---|
| 드롭다운, 팝오버 | `0 4px 12px rgba(0,0,0,0.10)` |
| 모달 | `0 8px 32px rgba(0,0,0,0.16)` |
| 토스트 | `0 4px 12px rgba(0,0,0,0.10)` |

카드에는 그림자를 사용하지 않는다. 색이 있는 그림자는 어디에도 사용하지 않는다.

## 6. 레이아웃

### 6.1 그리드

| 브레이크포인트 | 폭 | 구성 |
|---|---|---|
| `≥ 1280px` | 콘텐츠 최대 1280px | 사이드바 240 + 본문 |
| `1024 ~ 1279px` | 유동 | 사이드바 200 + 본문 |
| `768 ~ 1023px` | 유동 | 사이드바 접힘, 필터는 드로어 |
| `< 768px` | 유동 | 단일 열, 하단 탭 내비 |

### 6.2 상단 내비

높이 56px, 상시 고정(sticky). 데스크톱에서 햄버거 메뉴를 쓰지 않는다. 트랙이 3개뿐이므로 전부 노출한다.

```
┌──────────────────────────────────────────────────────────────────────┐
│  ML Code Arena    문제집  유형 설명  랭킹        [검색]  ◐  로그인   │
└──────────────────────────────────────────────────────────────────────┘
```

활성 트랙은 하단 2px accent 밑줄로 표시한다. 배경 채움이나 볼드 전환을 함께 쓰지 않는다.

### 6.3 문제집 목록

```
┌────────────────┬─────────────────────────────────────────────────────┐
│ 단계            │  문제집                        30문제 중 7 해결     │
│  1 수치·선형대수│  ┌──┬──────────────────┬─────────┬──┬─────┬─────┐  │
│  2 고전 ML      │  │ #│ 제목              │ 제한    │단│정답률│ 상태│  │
│  4 평가·검증    │  ├──┼──────────────────┼─────────┼──┼─────┼─────┤  │
│  5 최적화       │  │01│ 브로드캐스팅 shape│ numpy만 │ 1│  71%│  AC │  │
│                 │  │02│ L2 노름 직접 구현 │ numpy만 │ 1│  64%│  WA │  │
│ 태그            │  │03│ 공분산 행렬       │ numpy만 │ 1│  48%│   · │  │
│  numpy          │  │04│ 혼동행렬 계산     │ 직접구현│ 4│  55%│   · │  │
│  optimization   │  └──┴──────────────────┴─────────┴──┴─────┴─────┘  │
│  metrics        │                                                     │
│                 │                                                     │
│ 상태            │                                                     │
│  전체 / 미해결  │                                                     │
└────────────────┴─────────────────────────────────────────────────────┘
```

- 행 높이 40px. 한 화면에 최소 15행이 보여야 한다
- `#`, `정답률`, `상태` 열은 mono + tabular-nums
- 미해결 문제의 상태 열은 가운뎃점(`·`)으로, 빈 칸으로 두지 않는다
- 행 호버는 배경색 변화만. 이동·스케일·그림자 없음

### 6.4 문제 상세

좌우 분할이 기본이다. 코드업처럼 문제 페이지와 제출 페이지를 분리하지 않는다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ 05 · 1차원 경사하강법 구현      numpy만  sklearn 금지        단계 5   │
├───────────────────────────────┬──────────────────────────────────────┤
│ 문제                           │ solution.py            Python 3.11   │
│                                │ ┌──────────────────────────────────┐ │
│ f(x) = x² − 4x + 3 의 최솟점을 │ │ def solve(x0, lr, steps):        │ │
│ 경사하강법으로 찾아 반환하라.  │ │     ...                          │ │
│                                │ │                                  │ │
│ 엔트리포인트                   │ └──────────────────────────────────┘ │
│   solve(x0, lr, steps)         │            [ 제출 ]   10초 · 512MB   │
│ 허용 오차                      ├──────────────────────────────────────┤
│   rtol 1e-5 · atol 1e-8        │ 결과   WA  ·  케이스 2  ·  9ms       │
│                                │ ┌──────────────────────────────────┐ │
│ 예제                           │ │ 기대 shape   (3, 3)              │ │
│ ┌────────────────────────────┐ │ │ 실제 shape   (3,)                │ │
│ │ solve(0.0, 0.1, 50) → 2.0  │ │ └──────────────────────────────────┘ │
│ └────────────────────────────┘ │                                      │
│                                │                                      │
│ 선행 개념 → 경사하강법         │                                      │
└───────────────────────────────┴──────────────────────────────────────┘
```

- `≥1280px`: 좌 46% / 우 54%, 드래그 가능한 스플리터
- `1024~1279px`: 좌 40% / 우 60%
- `<1024px`: 탭 전환 (`문제` / `코드`), 결과는 코드 탭 하단

**제한 칩은 제목 줄에 상시 노출**한다. 접거나 툴팁 뒤에 숨기지 않는다. `FBD` 판정의 대부분은 제한을 못 본 데서 발생한다.

### 6.5 랭킹

```
┌────────────────────────────────┬─────────────────────────────────────┐
│ 랭킹                            │ 실시간 제출                         │
│  1  bryan          24   91%     │  14:03:22  bryan   05 경사하강  AC  │
│  2  hyunwoo        21   84%     │  14:03:11  jiwon   02 L2 노름   WA  │
│  3  jiwon          19   77%     │  14:02:58  hyunwoo 04 혼동행렬  AC  │
└────────────────────────────────┴─────────────────────────────────────┘
```

- 실시간 스트림은 새 항목이 상단에 추가되며, **120ms fade-in만** 적용한다. 슬라이드·바운스·펄스 없음
- 익명 제출은 스트림에 표시하지 않는다
- 순위·해결 수·정답률은 mono

### 6.6 개념 문서

읽기 전용 장문 콘텐츠. 최대 폭 **720px**, 좌우 중앙 정렬. 우측에 목차를 sticky로 둔다.

문서 하단에 연결된 문제 목록을 둔다. 개념 → 문제, 문제 → 개념 양방향 이동이 항상 1클릭이어야 한다.

## 8. 테마 전환

### 8.1 동작 규칙

- **기본값은 라이트.** `prefers-color-scheme`을 자동 적용하지 않는다
- 사용자가 명시적으로 전환한 값만 `localStorage`에 저장
- 저장값이 없으면 항상 라이트

### 8.2 구현

```html
<html data-theme="light">
```

```css
:root[data-theme="light"] { --bg-canvas: #FFFFFF; /* ... */ }
:root[data-theme="dark"]  { --bg-canvas: #16181C; /* ... */ }
```

**FOUC 방지**: `<head>` 최상단에 인라인 스크립트를 두어 CSS·JS 번들 로드 전에 속성을 확정한다.

```html
<script>
  var t = localStorage.getItem("mlca-theme");
  if (t === "dark") document.documentElement.dataset.theme = "dark";
</script>
```

### 8.3 전환 트랜지션

`background-color`와 `color`에 **150ms ease-out**을 적용한다. 그 이상은 적용하지 않는다. 페이지 전체가 천천히 물드는 효과는 어지럽다.

```css
@media (prefers-reduced-motion: reduce) {
  * { transition-duration: 0.01ms !important; }
}
```

### 8.4 토글 UI

상단 내비 우측, 아이콘 버튼 1개. 라벨 텍스트를 함께 두지 않는다. 아이콘은 Lucide `sun` / `moon`. `aria-label`은 전환 후 상태로 쓴다 — "다크 모드로 전환".

## 9. 모션

| 대상 | duration | easing |
|---|---|---|
| 호버 색 전환 | 120ms | `ease-out` |
| 드롭다운·모달 열기 | 150ms | `ease-out` |
| 테마 전환 | 150ms | `ease-out` |
| 스트림 항목 fade-in | 120ms | `ease-out` |
| 판정 확정 시 결과 패널 색 레일 | 200ms | `ease-out` |

**판정 확정 순간이 이 사이트의 유일한 이벤트 모션**이다. 사용자가 몇 초를 기다린 뒤 결과를 받는 순간이므로 여기에만 강조를 준다. 나머지 화면은 조용하게 둔다.

### 금지

- 무한 반복 애니메이션 (`pulse`, `bounce`, `ping`, floating)
- 페이지 진입 시 순차 fade-in (stagger)
- shimmer 스켈레톤 — 로딩은 정적 텍스트로 처리
- 호버 시 `scale > 1.02`, 회전, 기울임, 이동
- 카운트업 숫자 애니메이션

채점 대기 표시는 스피너 대신 **텍스트 상태 + 큐 순번**으로 한다. `채점 중 · 대기 3번째`. 진행 정보가 없는 스피너보다 유용하다.

## 10. 접근성

| 항목 | 기준 |
|---|---|
| 색 대비 | 본문 4.5:1, 큰 텍스트 3:1 이상 |
| 포커스 표시 | `2px solid var(--accent)` + `2px` offset, 항상 노출 |
| 색 단독 의존 금지 | 판정은 색 + 텍스트 코드 병기 |
| 키보드 조작 | 문제 목록 방향키 이동, `Enter` 진입 |
| 제출 단축키 | `Ctrl/Cmd + Enter` |
| 스크린리더 | 판정 결과 영역 `role="status"` + `aria-live="polite"` |
| 모션 | `prefers-reduced-motion` 존중 |
| 확대 | 200% 확대 시 가로 스크롤 없음 |

`aria-live`는 `polite`로 둔다. `assertive`는 사용자의 현재 작업을 끊는다.

## 11. 카피 원칙

### 11.1 톤

평서형, 사무적, 사과하지 않음. 이모지를 사용하지 않는다.

### 11.2 판정 메시지

| 판정 | 메시지 |
|---|---|
| `AC` | 정답입니다. |
| `WA` | 케이스 2에서 값이 다릅니다. |
| `TLE` | 10초 안에 끝나지 않았습니다. |
| `MLE` | 메모리 512MB를 넘었습니다. |
| `RE` | 실행 중 오류가 발생했습니다. |
| `CE` | 코드를 해석할 수 없습니다. |
| `FBD` | 이 문제는 `sklearn` 사용이 금지되어 있습니다. |
| `IE` | 채점 시스템 오류입니다. 자동으로 다시 채점합니다. |

**`FBD`는 어떤 규칙을 위반했는지 반드시 명시**한다. 침묵하는 오답은 학습을 방해한다. `IE`는 사용자 책임이 아님을 분명히 하고, 이 제출은 통계에 포함되지 않음을 덧붙인다.

### 11.3 빈 상태

| 화면 | 문구 |
|---|---|
| 제출 이력 없음 | 아직 제출한 코드가 없습니다. 1단계 문제부터 시작해보세요. |
| 필터 결과 없음 | 조건에 맞는 문제가 없습니다. 필터를 줄여보세요. |
| 랭킹 비어 있음 | 아직 해결된 문제가 없습니다. |

빈 화면은 분위기를 만드는 자리가 아니라 다음 행동을 지시하는 자리다.

### 11.4 동사 일관성

`제출` → 진행 중 `채점 중` → 완료 `채점 완료`. 한 동작은 흐름 전체에서 같은 이름을 유지한다. `Submit`·`전송`·`보내기`를 혼용하지 않는다.
