# ADR-0004: 세션을 JWT 대신 서버 세션 쿠키로 관리한다

- **상태**: 채택
- **일시**: 2026-08-05
- **관련**: M3, `docs/TECHNICAL.md` §8.1

## 맥락
인증 방식으로 JWT와 서버 세션 두 선택지가 있다. JWT는 무상태라 확장에 유리하다고 알려져 있다.

## 결정
서버 측 세션 ID를 HttpOnly·Secure·SameSite=Lax 쿠키로 전달한다. JWT를 쓰지 않는다.

## 근거
- Phase 1은 단일 호스트·단일 API 인스턴스다. 무상태성의 이득이 실현되지 않는다.
- 익명 세션 → 계정 승계 처리가 서버 상태를 어차피 필요로 한다. 세션과 익명 세션이 같은 저장소에 있으면 승계가 단순한 트랜잭션이 된다.
- 세션 무효화(로그아웃, 비밀번호 변경, 계정 정지)가 JWT에서는 블랙리스트를 별도로 만들어야 한다. 그 블랙리스트가 결국 서버 상태다.

## 결과 / 트레이드오프
- 이득: 즉시 무효화, 승계 처리 단순, 토큰 유출 시 대응 가능.
- 비용: API 다중 인스턴스로 갈 때 세션 저장소 공유 필요. Redis가 이미 있으므로 비용이 낮다.

## 검토한 대안
- **JWT** — 무상태 이득이 Phase 1에서 실현되지 않고 무효화 문제만 남는다. 기각.
