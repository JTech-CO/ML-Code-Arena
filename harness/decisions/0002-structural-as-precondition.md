# ADR-0002: `structural` 검사를 `tolerance`의 전제 조건으로 둔다

- **상태**: 채택
- **일시**: 2026-08-05
- **관련**: M1, M6, INV-6, `docs/TECHNICAL.md` §4.1.2

## 맥락
"경사하강법을 구현하라"는 문제에 `sklearn.LinearRegression`을 쓰면 수치 비교만으로는 통과한다. 이 경우 문제의 교육적 목적이 완전히 상실되며, 플랫폼이 캐글·리트코드와 구분되지 않는다.

## 결정
`structural`을 독립 채점 모드가 아니라 **`tolerance`의 선행 단계**로 둔다. 모든 문제는 `restrictions`를 필수로 갖고, AST 정적 검사를 통과한 뒤에만 수치 비교로 넘어간다. 위반 시 고유 판정 `FBD`를 반환한다.

검사는 `allowed_imports` 화이트리스트를 우선하고, `forbidden_*` 블랙리스트를 보조로 쓴다. 화이트리스트에 없는 import는 전부 거부한다.

## 근거
- 제한이 선택 사항이면 출제자가 빠뜨리고, 빠뜨린 문제는 라이브러리 한 줄로 풀린다. 필수로 두면 구조적으로 방지된다.
- 블랙리스트는 새 라이브러리가 나올 때마다 갱신해야 한다. 화이트리스트는 갱신 없이 안전하다.
- `FBD`에 고유 판정 코드를 주면 사용자가 "알고리즘이 틀렸다"가 아니라 "규칙을 위반했다"를 정확히 안다.

## 결과 / 트레이드오프
- 이득: 플랫폼 정체성 확보, 출제 실수 구조적 방지, 명확한 사용자 피드백.
- 비용: 문제마다 `allowed_imports` 작성 필요, 화이트리스트 누락 시 정답이 `FBD` 오탐(런북 23번).
- 한계: AST 검사는 정교한 우회를 완전히 막지 못한다. Phase 1의 목표는 "무심코 사용 방지"임을 명시한다.

## 검토한 대안
- **독립 모드로 분리** — 출제자가 안 붙이면 무의미. 기각.
- **실행 시점 import hook** — 우회 차단은 더 강하나 사용자 코드가 이미 실행된 뒤다. Phase 2 보완 수단으로 보류.
- **블랙리스트 단독** — 신규 라이브러리마다 갱신 필요. 기각.
