# ADR-0001: 채점을 큐 기반 비동기로 처리한다

- **상태**: 채택
- **일시**: 2026-08-05
- **관련**: M2, `docs/TECHNICAL.md` §2.3·§3.1

## 맥락
일반 알고리즘 저지는 1~2초 안에 채점이 끝나므로 동기 응답이 가능하다. ML 문제는 numpy 연산과 반복 최적화가 들어가 Phase 1의 짧은 문제도 수 초가 걸린다. HTTP 요청 안에서 채점을 끝내려 하면 타임아웃·커넥션 점유·워커 확장 불가 문제가 동시에 온다.

## 결정
제출은 `202 Accepted`로 즉시 접수하고, 채점은 Redis + BullMQ 큐를 통해 워커가 비동기로 처리한다. 클라이언트는 SSE로 결과를 수신한다. 큐는 `judge:fast` / `judge:slow` 둘로 분리한다.

## 근거
- 큐를 나중에 붙이면 API 계약(동기 응답 → 비동기 폴링)을 전부 갈아엎어야 한다. 초기 비용이 회수 비용보다 훨씬 싸다.
- 워커 수평 확장이 코드 변경 없이 가능해진다. Phase 2에서 학습 문제가 들어오면 필수가 된다.
- BullMQ는 재시도·타임아웃·중복 방지·stalled job 회수가 이미 구현되어 있다. Redis Stream을 직접 다룰 이유가 Phase 1 규모에서는 없다.

## 결과 / 트레이드오프
- 이득: 확장 경로 확보, API 안정성, `IE` 자동 재시도 가능.
- 비용: Redis 의존성 추가, 상태 전이(`PENDING`→`JUDGING`→`DONE`) 관리 필요, 고아 작업 회수 로직 필요.

## 검토한 대안
- **동기 채점** — 구현이 가장 단순하나 Phase 2 학습 문제에서 즉시 붕괴. 기각.
- **Redis Stream 직접 구현** — 의존성이 줄지만 재시도·회수를 직접 만들어야 한다. 이득 없음. 기각.
